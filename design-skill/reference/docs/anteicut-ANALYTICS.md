# Аналитика

## Что собирается

Одна таблица `events`, по строке на действие. В строке: время, идентификатор пользователя,
тип события, площадка, тип файла, качество, размер, длительность операции, был ли Premium и
сколько звёзд. Ссылки, названия публикаций, тексты и содержимое файлов не сохраняются.

| Событие | Когда |
| --- | --- |
| `open` | первое обращение из приложения за полчаса |
| `inspect` | разбор ссылки |
| `inspect_failed` | ссылка не открылась |
| `download` | файл доставлен в чат |
| `download_failed` | загрузка сорвалась |
| `purchase` | оплата прошла |
| `refund` | возврат сделан |

Записи копятся в памяти и сбрасываются в базу пачкой раз в 2 секунды, чтобы не нагружать SQLite
на каждое действие. «Онлайн» считается отдельно в Redis: отсортированное множество с отметками
времени, онлайн — те, кто был активен последние 3 минуты. Приложение стучится каждые 45 секунд,
пока вкладка видима.

## Что видит пользователь

`GET /api/stats/public` (кэш 20 секунд): сколько человек онлайн, сколько всего людей, сколько
скачано всего и сегодня. На главной это одна строка: «Сейчас онлайн 128 · сегодня скачали 4 210».
Чужие идентификаторы и чья-либо активность не раскрываются.

## Что видит администратор

`GET /api/admin/overview?days=30` и три вкладки панели.

**Обзор:** онлайн, скачано сегодня и всего, активные за день, неделю и месяц, график загрузок по дням, столбики
по часам суток, тепловая карта «день недели × час», разбивка по площадкам и типам файлов,
состояние очереди (в очереди, в работе, воркеры), доля ошибок, среднее время загрузки, трафик,
список площадок, которые чаще ломаются.

**Деньги:** звёзды за период и всего, число покупок, активные подписки, конверсия, выручка по
дням, часы покупок, последние 50 платежей с кнопкой возврата.

**Люди:** новые пользователи по дням и карточка по Telegram ID — имя, ник, даты, число загрузок,
потрачено звёзд, статус Premium, список платежей. Действия: выдать или снять Premium, сбросить
дневной лимит, заблокировать и разблокировать. Все действия пишутся в журнал `admin_audit`.

## Часовой пояс

Все группировки по дням и часам считаются в `ANALYTICS_TIMEZONE` (по умолчанию Europe/Moscow);
в базе время хранится в UTC. Смещение подставляется в SQL-запрос, поэтому «час пик» в панели
совпадает с местным временем аудитории.

## Правила графиков

Один график — одна серия и один тон, две шкалы на одной картинке не используются. У каждого
графика есть подсказка при наведении, сетка приглушена, подписи по осям редкие. Тепловая карта
использует один тон с изменением плотности, а не радугу.
